# Unsubscribe Security & Server-Side Request Forgery (SSRF) Defense

## Threat Model & Design Principles

Automated execution of outbound unsubscription requests presents a high-severity attack vector if not hardened against Server-Side Request Forgery (SSRF) and DNS rebinding attacks. A malicious sender could craft a `List-Unsubscribe` header pointing to internal infrastructure, cloud metadata endpoints (`169.254.169.254`), or private management consoles (`192.168.1.1`, `localhost`).

Email-LookUp employs a multi-layered defense-in-depth model implemented in `lib/intelligence/privacy/unsubscribe/unsubscribeSecurity.ts` and `unsubscribeExecutor.ts`.

---

## Technical Security Controls

### 1. Protocol Enforcement
- Strictly permits `https:` protocol.
- Rejects `http:`, `ftp:`, `file:`, `gopher:`, `data:`, or `javascript:` URIs.

### 2. Forbidden IP Address Ranges
The engine blocks all private, loopback, link-local, multicast, and cloud metadata CIDR ranges:

| IPv4 Range | Description | Purpose / Risk |
|---|---|---|
| `0.0.0.0/8` | Current network / default route | System routing misuse |
| `10.0.0.0/8` | RFC 1918 Private network | Internal cloud / VPC resources |
| `100.64.0.0/10` | Carrier-Grade NAT (RFC 6598) | Service provider infrastructure |
| `127.0.0.0/8` | Loopback address (RFC 1122) | Localhost services (`127.0.0.1`) |
| `169.254.0.0/16` | Link-Local / Cloud Metadata (RFC 3927) | AWS/GCP/Azure instance metadata (`169.254.169.254`) |
| `172.16.0.0/12` | RFC 1918 Private network | Internal container / VPC resources |
| `192.168.0.0/16` | RFC 1918 Private network | Home / Enterprise local area networks |
| `224.0.0.0/4` | Multicast | Network broadcast abuse |
| `255.255.255.255/32` | Limited Broadcast | Network discovery abuse |

### 3. IPv6 Prohibitions
- Loopback (`::1`, `0:0:0:0:0:0:0:1`)
- Unique Local Addresses (`fc00::/7`)
- Link-Local Addresses (`fe80::/10`)
- IPv4-Mapped IPv6 (`::ffff:0:0/96`)

### 4. Port Restrictions
- Strictly limits outbound connections to standard HTTPS port `443`.
- Any custom port (e.g. `https://example.com:8080/unsub`, `https://example.com:22/`) is rejected.

### 5. DNS Resolution & Rebinding Defense
- The hostname is resolved using pre-flight DNS lookup before issuing requests.
- All resolved IP addresses are evaluated against the blocked CIDR list. If any returned IP resolves to a private or reserved network, the request is aborted immediately.

### 6. Safe Redirect Handling
- Redirects are handled manually (`redirect: "manual"`).
- At each redirect hop (up to a maximum of 3 hops), the target `Location` header is parsed and re-submitted through the complete SSRF validation pipeline before following.
- Redirection to any private IP, non-HTTPS scheme, or non-standard port triggers an immediate abort.

### 7. Zero Credential Leakage
- Requests are dispatched with sanitized headers generated by `UnsubscribeSecurity.getSecureOutboundHeaders()`.
- Strips `Cookie`, `Authorization`, and session tokens.
- Ensures user authentication cookies or NextAuth session secrets are never forwarded to third-party unsubscribe endpoints.

### 8. Explicit User Confirmation Requirement
- Outbound requests cannot be triggered autonomously by automated background scanning.
- The `/api/privacy/unsubscribe` endpoint enforces `confirmedByUser: true` in the JSON request body.
